# 文件夹挑选器（folder-picker） v1.4.1

飞牛 fnOS 原生应用（.fpk）。**手动解压之后目录太乱？**用它把每一层子文件夹看清楚，勾选你真正要的那几个，一键移动/复制到媒体库。

界面按飞牛的设计语言做的：蓝白配色（主蓝 `#0F5FFF`）、大圆角白卡片、浅蓝高亮，打开就在飞牛桌面里以窗口形式出现。**上一次用的筛选条件和来源目录会自动记住**，下次打开接着用。

```
解压出来的东西长这样：
  Downloads/
    【电影天堂 www.dytt.com】最新剧集合集/
      ShowName.S01.1080p.WEB-DL/   ← 你要的
        ShowName.S01E01.mkv ...
        Subs/
      Sample/                      ← 不要
      URL.url                      ← 不要
    AnotherShow.2024.2160p/
      正片/                        ← 你要的
      花絮/                        ← 不要
```

装上本应用后：树形展开看清结构 → 勾选 `ShowName.S01.1080p.WEB-DL` 和 `正片` → 移到 `/vol1/1000/media/剧集`。完事。

## 先看界面（不用安装）

用浏览器打开 `preview/folder-picker-demo.html`：界面与正式版**完全一致**，只是数据是假的，用来先确认交互是不是你想要的样子。

## 功能

| 能力 | 说明 |
|---|---|
| **聚合视图（默认）** | 直接把各存储空间用户目录（`/vol*/1000`）下的文件夹**并成一个列表**，不必先点存储空间、再点 1000。同名文件夹来自多块盘时各自独立显示，并标出「vol1 / 同名 2 处」，勾谁就是谁 |
| 树形展示各级子文件夹 | 逐层展开，节点上直接标出「第 N 层 · 有几个子文件夹」 |
| **默认不显示文件** | 列表里只有文件夹，清爽；需要时勾「显示文件」即可看到 |
| 手动勾选 | 支持勾父带子；被上级带上的会置灰并标注「已被上级文件夹选中」，避免重复操作 |
| **按层一键勾选** | 统计出「第 1 层 / 第 2 层 / …」各有多少个文件夹，一行一层列出，每层【全选】【取消】，底部一行【全部层全选】【反选】 |
| **点清单定位** | 在「已勾选」里点任意一条，右侧目录树会自动展开祖先链、滚到该节点并高亮——文件夹几百个时不用再上下翻找 |
| 筛选条件 | 文件夹名包含（多关键词需全部包含）、排除特定名字（如 `@eaDir,Sample,#recycle`）、显示/隐藏空文件夹、隐藏系统目录（`.` 与 `@` 开头）、展开层数 1–6（默认 **3**） |
| **记住上次的设置** | 筛选条件（关键词、排除词、各开关、展开层数）和上次用的来源目录都自动记住，下次打开直接填回来；来源目录另外留**最近用过的最多 8 条**，输入框下拉或目录浏览器顶部一点即回 |
| 选中清单 | 实时显示勾选了几个、有多少文件、总体积（点「计算大小」） |
| 移动 / 复制 | 两种操作都支持；重名可选「自动改名 / 跳过 / 覆盖」；可「保留层级结构」 |
| 先预演 | 真正动手前先用【先预演一遍】看看会怎么搬，**一个字节都不动** |
| 导出清单 | txt / csv / json / bash 四种格式 |
| 进度与取消 | 后台执行，实时进度、随时取消（已搬完的不回滚） |

### 界面布局

```
┌ 来源目录 + 筛选（默认收成一行） ────────────────────────┐
├───────────────┬─────────────────────────────────────┤
│ 工作台（窄栏）  │  目录结构（占满剩余的宽度）             │
│  按层一键勾选   │   ▸ 包A                              │
│  已勾选 / 清单  │     ▸ 乱七八糟                        │
│  操作（目标/移动）│       ▸ ShowA.S01                   │
├───────────────┴─────────────────────────────────────┤
│ 筛选条件与来源目录会自动记住…      统一网关  v1.4.1     │
└─────────────────────────────────────────────────────┘
```

界面**没有标题栏那一排**：飞牛桌面小窗的标题栏上本来就写着应用名，页面里再来一遍纯属白占一行高度，所以直接从工具条开始（网关状态和版本号移到了页脚那一行）。

**「按层一键勾选」「已勾选」「操作」合并在左边同一个工作台里**，宽屏下它固定在左侧不随页面滚动；目录树在右边、自己带滚动条。所以就算一层里几百个文件夹，页面也始终只有一屏高——不必再在"树"和"操作按钮"之间来回滚。窗口窄于 1260px 时自动退回上下单栏，不至于挤成一团。

## 安装

1. 下载 `dist/folder-picker.fpk`（约 54 KB，x86 和 ARM 通用，因为它只依赖 Python 3）
2. 飞牛桌面 → **应用中心 → 手动安装（右上角）→ 上传 .fpk**
3. 选择安装到哪个存储空间 → 完成。桌面出现「文件夹挑选器」图标
4. 点击图标即可打开。**在飞牛桌面里以窗口形式打开**（`app/ui/config` 里 `"type": "iframe"`），不会另起浏览器标签页；经飞牛统一网关复用 NAS 登录态，无需再登录一次

也可以用命令行装：

```bash
# 在 NAS 上
appcenter-cli install-fpk /path/to/folder-picker.fpk
```

安装向导会让你填两个可选项：**默认来源目录**（一般填你解压压缩包的下载目录，例如 `/vol1/1000/Downloads`）和**默认目标目录**（例如 `/vol1/1000/media/剧集`）。留空也行，界面上随时能改。

## 使用流程

1. **来源目录**：**留空即可**——此时直接把各存储空间 `/vol*/1000/` 下的文件夹并成一个列表展示；也可以填（或点【浏览…】选）某个具体目录

> 【浏览…】打开的起点同样是**聚合层**：一进来就是各存储空间里的文件夹，选到就完事。想按盘逐级看时点【按存储空间】切到 `/vol1`、`/vol2`… 列表，面包屑第一级「存储空间」随时可以点回来。
> 起点不会是文件系统的 `/`——它不在应用的授权范围内，点进去只会报错。
2. 需要时点【筛选条件】展开筛选项，调好后再点【读取结构】。**展开层数默认 3 层**，正好看透「包名 → 里面一层 → 正片文件夹」这种典型结构
3. 看树、勾选；懒得一个个点就用左侧工作台的**按层一键勾选**，比如「第 2 层 全选」。第 1 层就是各存储空间里那些文件夹本身
4.【计算大小】确认一下要搬多少东西；想复核某一项，点「已勾选」里的那条，右侧的树会自动定位过去
5. 填**目标目录**，选**移动**还是**复制**，点【先预演一遍】看结果 → 确认后执行

> **不用每次重设**：筛选条件和来源目录会自动记住（存在浏览器本地），下次打开就填好了。来源目录输入框点一下会列出最近用过的目录，目录浏览器顶部也有一样的「最近用过」，一点就回去。
> 只有**真的读取成功**的目录才会被记住——手抖打错的路径不会下次还弹回来。

> 勾选语义：勾中某个文件夹 = **把整个文件夹（含里面所有内容）搬走**。所以不用去勾它的子文件夹。

## 关于权限（必看）

本应用以 **root** 身份运行（`config/privilege` 里 `"run-as": "root"`）。这是必要的：它的工作就是按你的指令在任意目录之间搬文件，而飞牛的用户目录默认互相不可读，普通应用用户根本看不到 `/vol1/1000/xxx`。

风险控制：

- **不暴露端口**：走飞牛统一网关（Unix Socket `app.sock`），由 fnOS 先校验登录态再转发请求，局域网里没有裸奔的 HTTP 接口
- IP 只对**管理员**可见（`"allUsers": false`）
- **没有删除源文件的功能**：只做移动/复制/导出。唯一的"替换"发生在你主动选择「覆盖」重名策略时（会有醒目的二次确认），而且替换的是**目标位置**的同名目录
- 所有路径必须落在白名单根目录（`/vol1`…`/vol32` 及系统授权目录）内，`..` 之类的穿越一律拒绝

## 配置

配置文件在应用数据目录：

```
/vol{n}/@appconf/folder-picker/settings.conf
```

| 项 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8484` | 仅本机调试用的 TCP 端口 |
| `BIND_HOST` | `127.0.0.1` | 调试监听地址 |
| `EXTRA_ROOTS` | 空 | 额外允许浏览的根目录，冒号分隔（挂载了外部存储时用得上） |
| `AGG_SUBDIRS` | `1000` | 聚合视图取哪一层作为「用户目录」，逗号分隔按顺序取第一个存在的。飞牛的用户数据在 `/vol{n}/1000`，一般不用改；某块盘上没有这一层时会自动退回该存储空间的根目录 |
| `AUTH_TOKEN` | 空 | TCP 直连时要求的令牌 |

改完到应用中心**重启应用**生效。

### 旧版 fnOS 的兼容模式（统一网关不可用时的退路）

统一网关要求 fnOS **V1.1.3100 及以上**。如果你的系统更老，图标点了打不开，可以改用端口直连：

1. 编辑 `settings.conf`，把 `BIND_HOST=127.0.0.1` 改成 `BIND_HOST=0.0.0.0`
2. 把 `app/ui/config.tcp` 覆盖到 `/vol{n}/@appcenter/folder-picker/target/ui/config`
3. 重启应用，然后浏览器访问 `http://NAS的IP:8484/`

⚠️ 端口模式没有网关的登录校验，**局域网内谁都能访问**（虽然它没有删除功能）。只在网关确实不可用时才用，并建议在防火墙里限制来源。

## 常见问题

**点了图标没反应 / 空白页**
先看日志：`/vol{n}/@appdata/folder-picker/info.log`。常见原因：fnOS 版本低于统一网关要求的版本（用上面的兼容模式），或没装 Python 3（fnOS 自带，一般不会）。

**希望它在飞牛桌面里开小窗，而不是另起一个浏览器标签页**
`app/ui/config` 里的 `"type"` 就是这个开关：`"iframe"` = 桌面内嵌窗口（**当前默认**），`"url"` = 新标签页。改成想要的值后覆盖到 `/vol{n}/@appcenter/folder-picker/target/ui/config`，再重启应用即可。
如果桌面图标的行为没变化，说明应用中心缓存了旧入口——SSH 上去执行一次 `systemctl restart trim_app_center.service` 就会重新读取。

**打开后满屏「请求失败 HTTP 404」，目录选择器里也一个文件夹都没有**
这是 1.1.0 修掉的一个真 bug。飞牛桌面入口的地址是 `/app/folder-picker`——**结尾没有斜杠**。旧版前端按"砍掉最后一个路径段"推导接口地址，把它算成了 `/app/`，于是所有请求都打到 `/app/api/...`，而网关只转发 `/app/folder-picker/**`，结果就是 404、页面空转。

现在的做法是**不猜、实测**：先拿当前地址的几个可能形态（当前地址当目录 → 各种前缀）逐个用 `/api/info` 试一次，谁真的返回本应用就认谁。服务端也同步放宽了前缀识别（大小写、重复斜杠、多套一层目录都能认出），两边互为兜底。

如果你看到的还是 404，说明装的仍是 1.0.0 的包，去应用中心更新到 1.1.0。

**点【浏览…】一直停在「加载中」**
早期版本有这个 bug：浏览起点是文件系统的 `/`，而 `/` 不在应用的授权范围内，请求被拒。现在起点是**聚合层**（各存储空间用户目录下的文件夹），不会再有这个问题。如果你装的是旧包，去应用中心更新一下。

**聚合视图里没看到我某个文件夹**
聚合视图列的是每个存储空间 `/vol*/1000/` 下的**第一层**文件夹。如果你要找的东西在更深处，点开对应节点逐层展开即可（默认展开 3 层）；如果它在别的目录（比如 `/vol1/1000/Downloads` 之外的挂载点），把来源目录填成那个目录，或用 `EXTRA_ROOTS` 把挂载点加进白名单。
另外，某块盘上没有 `1000` 这一层时，会自动退回该存储空间的根目录来列——所以自建的白名单目录也能正常参与聚合。

**看不到我的目录**
检查路径是否在允许范围内。外部存储挂载点可以通过 `EXTRA_ROOTS` 加进来。

**存储空间里怎么看不到 `@appdata`、`@appcenter` 这些目录？**
它们被当成系统目录默认隐藏了（`.` 和 `@` 开头的一律隐藏）。确实需要访问时，把筛选区的「隐藏系统目录」关掉。

**有些文件夹没显示出来**
默认隐藏「真的什么都没有」的空文件夹和系统目录——用筛选区的「显示空文件夹」「隐藏系统目录」两个开关控制。注意**只含文件、没有子文件夹的目录不会被隐藏**（正片目录通常就是这样，隐藏它就没法干活了）。

**勾了半天发现选错了一层**
点工作台「已勾选」右上角的【清空】重来，或对某一层点【取消】。

**一层里几百个文件夹，界面太乱 / 找不着东西**
现在的布局就是为这个准备的：目录树自己滚动，工作台固定在左边，页面不会越滚越长。
- 先用**筛选条件**把范围收窄（名称包含某关键词、排除 `Sample` 这类）
- 用**按层一键勾选**批量处理，不用一个个点
- 想核对某一项，在「已勾选」里点它，右边的树会自动展开并滚到那个节点
- 树里【全部收起】之后再按层展开，比一层层点开快

**顶部的「筛选条件」点了没反应？**
它只是把筛选项展开/收起，默认是收起的（界面因此只占一行）。**折叠状态下筛选条件依然生效**，而且按钮上会直接标出「筛选条件 N 项」，不会让人误以为没筛选。

**我上次的设置怎么没被记住？**
记住的东西存在**浏览器的本地存储**里，按页面地址区分，所以：

- 从飞牛桌面图标打开（网关地址）和直接用 `http://NAS:IP:8484/` 打开（兼容模式）算两份，互不串
- 换浏览器、用无痕窗口、清理浏览器数据都会丢
- 如果页脚写着「**这个窗口禁用了本地存储，本次改的条件不会被记住**」，说明这个窗口不让存（个别加固的内嵌窗口会这样）——功能照常，只是不记忆

想手动清掉：浏览器开发者工具 → Application/存储 → Local Storage → 删掉 `folder-picker.prefs.v1`、`folder-picker.roots.v1` 两条即可。

**目标目录也会被记住吗？**
会，但只在**你真的用它执行过一次**（含预演）之后才记——随便打进去又改掉的不会留。同理，来源目录只在**读取成功**之后才记。

**确认框的「确认执行」点了没反应？**
执行移动/复制前会弹一个页面内自绘的确认框（不是浏览器原生弹窗）——因为 iframe 里原生弹窗常被浏览器拦截，点了会静默失败。如果你看到的是浏览器自带的原生确认框，说明装的是旧包，更新一下。

**我能批量把选中的文件夹删掉吗？**
不能，而且是有意为之。本工具只搬不删；要清理源目录，用完确认无误后自己在文件管理器里删更放心。

## 从源码构建

```bash
# 1. 下载官方打包工具
curl -L -o fnpack https://static2.fnnas.com/fnpack/fnpack-1.2.3-linux-amd64
chmod +x fnpack && sudo mv fnpack /usr/local/bin/

# 2. 打包（含打包前自检 + 生成 dist/folder-picker.fpk）
python3 tools/build_fpk.py

# 3. 跑测试（后端接口 193 项，不需要装 7z、不需要占用端口）
python3 tests/test_api.py

# 3b. 前端界面测试（135 项，用 jsdom 真跑页面脚本；另需本地调试服务，见文件头注释）
#     测试会自动重建演示数据（它会真的搬文件），所以可以反复跑
node tests/test_ui.js

# 4. 重新生成图标 / 演示页
python3 tools/make_icons.py
python3 tools/make_demo.py
```

`tools/build_fpk.py` 会在打包前自检：必需文件是否齐全、JSON 是否合法、shell 脚本是否为 LF（Windows 上编辑最容易踩的坑，CRLF 会让脚本在 NAS 上直接报 `bad interpreter`）、网关前缀与 `appname` 是否一致。

## 工程结构

```
folder-picker/
├── manifest                     应用元数据（appname / 版本 / 入口 / 网关）
├── ICON.PNG  ICON_256.PNG       应用图标（64 / 256）
├── config/
│   ├── privilege                运行身份（root，见上文说明）
│   └── resource                 数据共享声明（本应用不需要额外共享目录）
├── cmd/                         生命周期脚本（start/stop/status + 安装升级卸载）
│   └── main                     ★ 探测 Python、拉起服务、PID 管理、日志
├── wizard/                      安装向导（默认来源/目标目录）、卸载向导
├── app/
│   ├── server/folder_picker.py  ★ 后端：REST API + 文件搬运 + 进度任务
│   ├── www/index.html           ★ 前端：单文件界面（无构建步骤、无外部依赖）
│   └── ui/                      桌面入口与图标
├── tests/
│   ├── test_api.py              193 项接口自测（进程内驱动 HTTP 处理器）
│   └── test_ui.js               135 项界面测试（jsdom 真跑页面脚本）
├── tools/                       图标生成、打包、演示页生成
├── preview/folder-picker-demo.html   界面预览（假数据）
└── dist/folder-picker.fpk       安装包
```

技术选型说明：后端只用 **Python 3 标准库**（`http.server` + `socketserver`），没有第三方依赖，所以包只有 40 KB、不需要联网装东西、x86/ARM 通用。前端是一个 HTML 文件，改完即生效，不用 npm。

## 已知限制

- **不做解压**：它只负责"看懂结构 + 搬运"。解压用飞牛文件管理器、100zip 或 Unpackerr
- **不做删除**：故意的（见上文）
- 超大目录有保护上限：树最多 20000 个节点、单层最多列 5000 项、统计最多 20 万个文件（超出会提示"已截断"），避免把 NAS 拖卡
- 一次最多处理 2000 个文件夹
- 同时勾选父目录和它的子目录时，只按父目录处理（避免自相矛盾的搬运动作）
